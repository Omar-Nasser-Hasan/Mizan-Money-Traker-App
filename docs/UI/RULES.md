# docs/ui/RULES.md — rules for building the new Mizan interface

1. Source of truth. Each screen lives in docs/design/stitch/[folder]/. Use screen.png for the look and code.html for exact spacing, colors, copy and icon names. Tokens come from docs/design/stitch/obsidian_champagne/DESIGN.md. Build native Jetpack Compose. Never use a WebView or paste HTML. Match layout, spacing, colors, type, icons and states; it does not need to be pixel-identical.
2. Where the screens and the older palette disagree, the screens win. In particular the dark canvas is #121316, not #202124. True black stays an option.
3. Typography is Manrope only. The Fraunces serif from the earlier pack is dropped.
4. All numbers, names, dates and counts in the designs are placeholders and are inconsistent between screens (gold is 2,742 per gram on one screen and 5,600 on another). Never copy them. Every figure comes from real data through ViewModels.
5. Ignore these mock artifacts: the fake status bar (9:41, signal, battery); the person/avatar icon in top bars; the pound sign (always EGP or the account's own currency); the Breakdown and Analytics tabs behind period_selector_modal; 'Auto-debit active' on the credit card (planned payments never post by themselves); the goals card 'Allocating ... next payday' and any other AI-style insight copy.
6. Backend first. Bind to existing repositories, use cases and calculators. Do not change domain rules, ledger semantics or the schema. If a screen needs something that does not exist, build it only if it is on the allowed-additions list below; otherwise hide the element and add it to docs/ui/GAPS.md. Never fake data.
   Allowed additions: fix balance (ADJUSTMENT), duplicate record, pay-card shortcut (prefilled transfer), trash screen over the existing soft delete, record and split template CRUD, statement and due day fields, unrealized FX gain, goal ETA, custom and all-time periods, share-chart-as-image, planned 'skip'. Any addition that touches the schema needs a Room migration and a migration test.
7. States. Every screen implements loading (skeleton), empty (EmptyState with one call to action), error, populated, and stale or offline where prices or rates are involved. Amounts honor hide-amounts. User text may be Arabic and must render right-to-left correctly. Layouts survive 1.3x font scale. 48dp touch targets. TalkBack labels on icons and charts.
8. Amounts use one AmountText: Western digits, two decimals, EGP prefix, tabular figures. Expense coral with a minus, income teal with a plus, transfer blue-gray with arrows and no sign, investment violet with an 'Invested' tag. Never color alone.
9. Icons: Material Symbols Rounded, outlined, weight 300, through one MzIcon using the ligature names found in code.html. Bottom navigation icons come from mizan_home (the approved reference); the other screens show slightly different icons, ignore them.
10. Hosting. New screens live in app/src/main/kotlin/app/mizan/ui/v2/ next to the old UI, behind the runtime flag 'New interface' (default off until prompt P15). Do not delete old UI before P15.
11. Tests. Each screen gets a Compose UI test for populated, empty and loading states with fake repositories; one integration test per flow on an in-memory Room database proving the action writes the right rows; and screenshots saved to docs/ui/shots/pNN/ for my review.
12. Performance: the SPEC section 3 budgets. Lazy lists with stable keys; no work in composition; charts draw from precomputed series.
13. Process: small commits (one per screen), the full CI command green before every commit, update docs/CHANGELOG.md, list anything skipped or blocked in docs/ui/GAPS.md. If you need input from me, write it in docs/BLOCKERS.md, finish everything else, then stop.
