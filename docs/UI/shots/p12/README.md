# P12 acceptance and captures

The captures are generated by `P12ScreensInstrumentedTest` on the API 37 emulator from real Compose screens with controlled presentation data. Captures draw the mounted Compose view to a bitmap on the UI thread; this avoids blank startup frames from the emulator graphics pipeline. They cover Welcome, editable accounts with EGP/USD buckets, the default income split, a selected category tree, a search with no results, Secure it, and the locked gate. No performance measurement was taken.

Validation on 2026-10-19: the required CI command passed (72 domain and 47 app unit tests), and all eight targeted emulator tests passed. View captures exclude native system bars and the keyboard; the empty-search capture shows the keyboard-reduced app viewport.

## Acceptance coverage

- Clean install with chosen data: `OnboardingIntegrationTest` verifies exact account/bucket rows, opening balances, one default split, archived categories and stable category IDs; `V2OnboardingDraftTest` verifies defaults, custom/single-account splits and process-restored drafts. The full clean-install navigation is a documented P12 phone step in `docs/PHONE_CHECKLIST.md`.
- Skip defaults: draft/domain tests cover zero balances, 10/40/50 percentages and all seeds; the P12 phone step covers skipping the whole flow.
- Restore from Welcome: the Welcome UI test exercises the restore entry; the existing `BackupArchiveInstrumentedTest` covers encrypted archive restoration of every table and receipts. File-picker navigation, wrong-passphrase handling and restart to Home are documented phone steps.
- Lock gate: `LockGateTest` covers cold start, process death, enable/disable, exact timeout boundaries and PIN success during background. The Compose test asserts private amounts are absent before authentication and present afterwards.
- Hardware biometric/PIN, FLAG_SECURE/Recents, backup export and accessibility: one-line phone checks are in `docs/PHONE_CHECKLIST.md`; emulator captures cannot certify handset behavior.
